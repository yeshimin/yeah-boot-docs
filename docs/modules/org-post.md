# 组织与岗位

组织和岗位用于描述用户的业务归属。它们与角色权限是独立关系：组织岗位不自动产生接口权限。

## 组织管理

组织采用树形结构，支持查询、创建、编辑、移动上级和删除。

创建或编辑时需要检查：

- 上级组织存在且可用。
- 不能把节点移动到自身下面。
- 不能把节点移动到自己的后代下面。
- 同一父节点下的业务名称或编码符合当前唯一性规则。

删除有子节点的组织时，应明确提示影响范围并二次确认；后端负责最终的树关系校验或级联策略。

## 岗位管理

岗位使用分页列表维护，包含编码、名称、状态、排序和备注。创建、编辑和删除分别使用专用接口，查询和详情可以使用启用的通用 CRUD 入口。

新增弹窗每次打开必须使用明确默认值，不能残留上一次编辑数据。

## 用户关联

用户创建和编辑都可以携带组织 ID、岗位 ID。后端对 ID 集合进行存在性检查：

- 新绑定的数据必须存在并满足可选条件。
- 已绑定但后来被禁用的数据可以回显。
- 禁用项不能再次新增选择。
- 用户可以取消已有禁用项后保存。

## 状态语义

禁用组织或岗位不会直接踢用户下线，也不会改变角色权限。页面选择组件应将禁用项显示为“名称（禁用）”并置灰，已有绑定仍可回显。

## 权限建议

组织和岗位分别配置查询或树、详情、新增、编辑和删除权限。页面加载所必需的列表接口应作为接口资源授权，不要仅依赖按钮权限。
