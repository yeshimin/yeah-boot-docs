# 日志与系统参数

## 系统日志

管理端关键写操作通过 `@SysLog` 记录操作名称、类别、触发类型、执行结果、耗时和上下文。日志列表默认按时间倒序，最新记录优先展示。

页面支持：

- 按条件分页查询。
- 查看单条日志详情。
- 通过 `traceId` 关联应用日志和 SQL 日志。

`triggerType` 默认表示系统触发；`category` 默认 `0-无`，只有需要分类展示时才指定枚举。注解不再提供无实际使用价值的输入、输出记录开关。

系统日志可能包含异常与业务参数摘要，生产环境应设置保存期限，禁止记录密码、Token、验证码和密钥原值。

## 系统参数

系统参数页面维护可以运行时调整的非敏感业务配置，支持新增、编辑、删除、分页查询和刷新缓存。

保存时后端检查：

- 参数键是否属于允许的内置定义。
- 值类型是否与定义一致。
- 整数、长整数和布尔值是否能正确解析。
- 状态是否有效。

## 缓存机制

```text
sys_config 中全部启用参数
        ↓
构建完整 Map 快照
        ↓
写入 Redis 单一缓存键
        ↓
业务按 SysConfigEnum 读取
```

应用启动完成后加载缓存；新增、编辑和删除完成后刷新。Redis 键丢失或内容损坏时，首次读取会尝试从数据库重建。

手动“刷新缓存”适用于：

- 直接修改过数据库。
- 自动刷新失败。
- 排查缓存与数据库不一致。

## 默认值

每个参数在 `SysConfigEnum` 中同时定义键、类型和默认值。数据库没有有效值时使用默认值，因此新增代码配置时不要求数据库必须同步存在一条记录，但正式发布应补齐管理数据和备注。

## 安全边界

数据库、Redis、JWT、短信密钥和对象存储凭据不能进入 `sys_config`。这些内容属于启动时安全配置。系统参数日志可以打印参数键和普通值，但模板标识等敏感或供应商相关内容统一显示为 `******`。
