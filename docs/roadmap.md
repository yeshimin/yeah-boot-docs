# 项目路线图

路线图用于记录方向，不承诺固定交付时间。优先级根据真实项目需求调整。

## 近期完善

- 补充 MockMvc、数据库和前后端端到端测试；登录限制、上传策略、幂等、加密与日志脱敏等核心安全单元测试已具备。
- 建立 SonarQube 等代码质量检查。
- 完善代码生成对 BigDecimal、decimal 和 tinyint 等字段的映射。
- 增加运行监控、健康检查和 Demo 数据重置流程。
- 持续维护 API、配置和权限资源文档。

## 暂缓

- 多因素鉴别，例如密码后短信、TOTP 或硬件证书。
- 多租户。
- 多数据源。
- PostgreSQL 等多数据库支持。
- Access Token + Refresh Token。
- 更复杂的全局限流和登录风控。
- 资源权限继承与再分配。
- 大规模异步导入导出。

## 需要业务驱动

- 审计日志哈希链/HMAC、独立审计存储或远程审计写入。
- 系统/安全/审计管理员的职责分离与角色互斥。
- 敏感字段存储加密、密钥管理和检索策略。
- 关键系统参数的审批、版本历史、差异对比和回滚。
- 系统参数继续扩展哪些在线配置。
- 文件引用是否升级为完整引用计数。
- App 端手机号、账号和多种登录方式的产品规则。
- 首页统计指标和可视化内容。
- 数据范围、组织权限和租户隔离。

## 原则

- 已有简单机制能满足需求时，不提前引入复杂架构。
- 安全、数据一致性和可恢复性优先于功能数量。
- 新能力必须同时考虑数据库、后端、前端、权限资源、测试和文档。
